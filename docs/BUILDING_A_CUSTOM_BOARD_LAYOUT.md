# Building a custom board layout

Use this when you have a physical board that wasn't generated by
`board/generate_charuco_board.py` (so you can't be sure it matches
OpenCV's internal ChArUco layout convention) but has individually
identifiable ArUco markers at known, fixed positions on a grid.

## Why this is a manual, not automatic, step

It would be possible to write code that photographs the board and
automatically clusters detected marker pixel positions into a grid. That
code was deliberately **not** written for this repo: automatic grid
clustering from a single photo is fragile under perspective/rotation, and
if it silently mis-assigns even one marker's grid position, every
downstream calibration (camera intrinsics, LiDAR extrinsics, RGB-thermal
extrinsics) is quietly wrong with no obvious symptom -- the kind of mistake
that's expensive to catch after the fact. Looking at one photo directly
and reading off the grid by eye takes a few minutes and has no such
failure mode.

## Schema: `config/custom_board_layout.yaml`

```yaml
dictionary: DICT_5X5_100   # whatever board/identify_board_dictionary.py found
markers:
  - id: 3
    corners_3d:            # board-frame (z=0 plane) corners, TL/TR/BR/BL order --
                            # same order cv2.aruco.detectMarkers returns, so they
                            # line up directly with detected image corners
      - [0.0045, 0.0045, 0.0]
      - [0.0135, 0.0045, 0.0]
      - [0.0135, 0.0135, 0.0]
      - [0.0045, 0.0135, 0.0]
  - id: 7
    corners_3d: [...]
  # one entry per marker on the board
```

Units are metres. The board's own origin/axis choice doesn't matter (any
consistent origin works -- e.g. top-left corner of the whole board, x
right, y down), since every calibration here only cares about the board's
own internal geometry, not where its origin sits in the world.

## How to build it (the process used for this project's own board)

1. Get a clear, well-lit, roughly fronto-parallel photo of the board:
   ```
   python3 board/grab_one_frame.py /landfill/rgb/image_raw board/my_board_photo.png
   ```
2. Identify the dictionary:
   ```
   python3 board/identify_board_dictionary.py board/my_board_photo.png
   ```
3. Run plain marker detection on the photo and print each marker's id and
   pixel centre (a few lines of cv2.aruco.detectMarkers -- see
   `calibration/common/custom_board.py`'s `detect_markers`), so you have a
   list of (id, approximate pixel position).
4. Look at the photo next to that list, and for each marker work out its
   (row, column) in the physical grid by eye.
5. Compute each marker's 4 corner positions from (row, column) and the
   known `square_length_m` / `marker_length_m`:
   - Square (row, col)'s top-left corner is at
     `(col * square_length_m, row * square_length_m)`.
   - The marker is centred in its square with margin
     `(square_length_m - marker_length_m) / 2` on each side, so the
     marker's own TL corner is
     `(col * square_length_m + margin, row * square_length_m + margin)`,
     and TR/BR/BL follow by adding `marker_length_m` in x and/or y.
   - z is always 0 (the board is planar by construction).
6. Write the result to `config/custom_board_layout.yaml` in the schema
   above.

This file documents the *process*; the actual board/identify_board_dictionary.py
and calibration/common/custom_board.py do the parts of it that are safe to
automate (dictionary identification, detection, and all the downstream
calibration math) -- only the grid-position read-off in steps 3-4 is
manual, and only because getting it wrong silently is worse than the few
minutes it takes to do by hand.
